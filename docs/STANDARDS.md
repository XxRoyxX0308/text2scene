# 美術與效能規範

這份文件把「怎麼讓場景不像塑膠、又跑得順」寫成具體數字，並標出管線裡由哪一步負責。
管線的腳本已經照這些數字實作；手動調整或新增資產時也照這裡做。

## 1. 塑膠感從哪裡來，管線怎麼處理

| 原因 | 管線的對策 | 負責的步驟 |
|---|---|---|
| 材質太乾淨、顏色均勻 | 道具依 `condition` 烘焙髒污（凹處、靠地面處）與邊緣磨損；牆地面用世界座標的大尺度變化（macro variation）打破重複 | `20_bake_props.py`、引擎主材質 |
| 粗糙度單一（最大元兇） | 粗糙度一律加大尺度擾動；來源幾乎均勻時強制拉開；髒處更粗、磨亮的邊更滑 | `textures.weather()` |
| Albedo 過白、過黑、過飽和 | 基色亮度限制在 sRGB 30–240，飽和度上限 0.85 | `textures.clamp_albedo()` |
| AI 貼圖烘進了光影 | 去光影（`delight`）壓平大尺度明暗；沒有可靠的全自動方法，只能減輕 | `textures.delight()` |
| 邊緣完美直角 | 模組件所有外露硬邊倒角 12 mm 並用加權法線；道具硬邊切分平滑群組 | `21_build_kit.py` |
| 光照太平 | 引擎內三層光源 + 全域光照（Lumen / 光照探針）+ 天空 + 高度霧 + 反射探針 | 引擎匯入器 |
| 同一張貼圖重複鋪滿 | macro variation、細節法線、貼花、散佈雜物 | 引擎主材質、`30_layout.py` |
| 只有大結構、沒有生活痕跡 | 每個空間要求散佈物與貼花，`budget.json` 會列出數量 | `layout.json` 的 `scatter` / `decals` |

## 2. 材質

### 2.1 貼圖組與通道

每個材質都輸出同一套標準貼圖（`textures.py`）：

| 檔名 | 內容 | 色彩空間 |
|---|---|---|
| `T_<名>_BC.png` | 基色（貼花為 RGBA，A 是不透明度） | sRGB |
| `T_<名>_N.png` | 切線空間法線，**OpenGL（+Y 向上）**；Unreal 匯入時自動翻綠色通道 | 線性 |
| `T_<名>_ORM.png` | R = AO、G = 粗糙度、B = 金屬度（Unreal 用） | 線性 |
| `T_<名>_MASK.png` | R = 金屬度、G = AO、B = 細節遮罩、A = 平滑度（Unity URP Lit / HDRP Mask Map / Built-in Standard 共用） | 線性 |

### 2.2 數值範圍

| 項目 | 規範 |
|---|---|
| 基色亮度 | sRGB 30–240（煤灰約 50、新雪約 240，沒有東西是純黑或純白） |
| 飽和度 | ≤ 0.85；強烈顏色只出現在小面積（警示漆、標示） |
| 粗糙度 | 任何表面都要有變化；完全均勻（標準差 < 0.05）會被強制加擾動 |
| 金屬度 | 只有 0 或 1 附近；0.3–0.7 只出現在髒污金屬的過渡區 |

### 2.3 貼圖密度（texel density）

所有資產以「每公尺多少像素」統一，避免小東西用 4K、大牆面卻糊掉。

| 類別 | 目標 px/m | 說明 |
|---|---|---|
| `hero` | 1024 | 玩家會近看的主角道具 |
| `prop` | 512 | 一般家具、設備 |
| `small` | 512 | 小雜物（面積小，實際貼圖會自動縮到 256–512） |
| 模組件與表面材質 | ≥ 512 | `tile_m` 公尺鋪一次，2K 貼圖鋪 2 m = 1024 px/m |

`20_bake_props.py` 依模型表面積與 UV 面積自動選貼圖邊長（2 的次方，256–4096），並把結果記在 `asset.json` 與報告裡。
表面材質的 `tile_m` 最好能整除模組尺寸（模組 2 m → `tile_m` 用 0.5、1、2），相鄰模組件的貼圖才會接得起來。

### 2.4 打破重複

1. **macro variation**：`export/shared/T_Macro.png` 三層不同尺度的無縫噪波，主材質以世界座標取樣（約 8 m 一個週期），調整亮度與粗糙度。強度用材質的 `macro`（預設 0.12，戶外大面積 0.2）。
2. **細節法線**：`T_DetailNormal_N.png` 以 4 倍密度疊在主法線上（`detail`，預設 0.4），近看才看得到。
3. **貼花**：髒污、水漬、裂痕、刮痕、手印。每個空間至少幾張，走廊與門口最多。
4. **散佈物**：紙張、箱子、垃圾桶、落葉、碎石，依空間狀態決定。

## 3. 幾何

| 項目 | 規範 |
|---|---|
| 單位與座標 | 公尺；+X 東、+Y 北、+Z 上；物件正面朝 -Y（yaw 0） |
| 原點 | 道具：底面中心；牆面掛件（`image_slab`）：背面底邊中心；模組牆：格線上的底邊中心 |
| 命名 | 網格 `SM_`、材質實例 `MI_`、主材質 `M_T2S_`、貼圖 `T_`、碰撞 `UCX_<網格名>_NN` |
| 倒角 | 模組件外露硬邊 12 mm（`kit.bevel`），門窗框 3–4 mm；加權法線 |
| 三角化 | 匯出前全部三角化，烘焙與引擎用同一套三角形，法線貼圖才不會錯 |
| 內部殼 | TRELLIS 常在模型內留下封閉的內殼（實測一張椅子 9.7 萬面裡有 4.8 萬面看不到），一律刪除 |
| 碰撞 | 道具預設包圍盒，椅子這類用 `convex`，小雜物 `none`；模組件每格一個盒子，門洞不擋 |

### 3.1 LOD

| 類別 | LOD 面數比例（相對 LOD0） | 切換螢幕比例 |
|---|---|---|
| `hero` | 1、0.5、0.25、0.1 | 1.0 / 0.4 / 0.15 / 0.05 |
| `prop` | 1、0.5、0.2 | 1.0 / 0.4 / 0.15 |
| `small` | 1、0.35 | 1.0 / 0.4 |

硬表面先做平面溶解（planar，平坦處合併，不會跑形）再用 collapse 補到目標面數；有機形狀直接 collapse。
Unreal 預設對不透明網格開 Nanite（LOD 由引擎處理，匯入器不再匯入 LOD1+）；Unity 用這些 LOD 建 LODGroup。

### 3.2 LOD0 面數參考

| 物件 | LOD0 三角面 |
|---|---|
| 小道具（< 0.5 m） | 2 000–8 000 |
| 一般家具、設備 | 10 000–40 000 |
| 主角道具、大型物件 | 40 000–80 000（Unreal Nanite 可更高） |
| 模組牆、地板 | 10–700（形狀本身就簡單） |

## 4. 三個距離的細節層次

| 距離 | 看什麼 | 管線裡的來源 |
|---|---|---|
| 遠景 | 輪廓、色塊分布、霧 | 模組件的量體、天空、高度霧、戶外遠景量體 |
| 中景 | 物件組合、破損、管線、植被 | 道具、散佈物、燈具、門窗框 |
| 近景 | 材質細節、倒角、縫隙、髒污 | 倒角、細節法線、道具的烘焙髒污、貼花 |

驗收時三個距離都要看：每個空間的審查鏡頭至少一張全景、一張中景，主角道具加一張近景。

## 5. 燈光與後處理

### 5.1 三層光源

| 層 | 做什麼 | `layout.json` |
|---|---|---|
| 主光 | 決定方向與明暗（太陽、主要燈具陣列） | `lighting.sun`、`lights` 的 `grid` |
| 補光 | 間接光、天空光，讓暗部有資訊 | 引擎的 GI + 天空光（自動） |
| 重點光 | 讓主體跳出來（聚光、櫃台燈、螢幕） | `lights` 裡的 `spot`，開 `shadows` |

### 5.2 參考數值

| 光源 | 數值 |
|---|---|
| 晴天太陽 | 75 000–100 000 lux，5500–6000 K |
| 陰天 | 10 000–20 000 lux，6500–7500 K |
| 辦公室照度 | 300–500 lux：每 3 × 3 m 一盞 2 000–3 000 lm，4000–4500 K |
| 住宅暖光 | 800–1 600 lm 一盞，2700–3000 K |
| 緊急燈、警示燈 | 200–600 lm，有色 |
| 曝光範圍 | 室內約 EV 5–8，室外晴天約 EV 13–15；`post.exposure` 設成能涵蓋全場景的範圍 |

### 5.3 後處理

| 效果 | 預設 | 原則 |
|---|---|---|
| Tonemapper | ACES / filmic（Unreal 預設、Unity 匯入器設 ACES） | 不要用線性 |
| Bloom | 0.3–0.4 | 過量會廉價 |
| AO | 0.5 | 防止物件漂浮 |
| Vignette | 0.2–0.3 | 點綴 |
| Film grain | ≤ 0.05 | 點綴 |
| 色彩校正 | saturation 0.9–1.0、contrast 1.0–1.1、white balance 依氣氛 | 統一整個世界的色調 |
| 高度霧 | density 0.01–0.03，有空氣感即可；室內場景可開 volumetric 做光束 | |

## 6. 效能預算

`30_layout.py` 每次都會算一次，寫在 `export/budget.json`，超過就印出 `BUDGET` 警告。預設值（可在 `assets.json` 的 `budgets` 覆寫）：

| 項目 | 上限 | 理由 |
|---|---|---|
| 每個空間 LOD0 三角面 | 1 500 000 | 中階 GPU 在不靠 Nanite 時仍能跑 60 fps 的量級 |
| 每個空間實例數 | 1 500 | draw call / 剔除成本 |
| 重疊的有陰影燈 | 4 | Unreal stationary 燈的硬限制；其餘小燈關陰影 |
| 每個空間貼花 | 60 | 貼花是螢幕空間成本 |
| 每個空間半透明物件 | 40 | overdraw |
| 全場景貼圖記憶體（壓縮後，含 mip） | 2 048 MB | |
| 材質數量 | 120 | 共用材質才能合批 |

### 6.1 引擎端已經做好的效能設定

| 項目 | Unreal | Unity |
|---|---|---|
| 重複物件 | 同一個 StaticMesh 的實例自動 instancing；不透明網格開 Nanite | 材質開 GPU Instancing，物件標 Batching Static |
| LOD | Nanite（或匯入的 LOD） | LODGroup |
| 剔除 | 自動 | 物件標 Occluder / Occludee Static，烘焙 Occlusion Culling 後生效 |
| 全域光照 | `gi: dynamic` → Lumen；`baked` → Lightmass + Importance Volume | 每個空間 Light Probe Group + Reflection Probe；`-t2sBake` 烘焙 |
| 貼圖 | Mipmap、串流（引擎預設） | Mipmap、Mip Streaming |
| 燈光 | `gi: dynamic` 時全部 Movable；`baked` 時依 `mobility` | Baked / Mixed / Realtime 依 `mobility` |

### 6.2 找瓶頸

先量再改：

- Unreal：`stat unit`、`stat gpu`、`ProfileGPU`（GPU Visualizer）、Unreal Insights；視圖模式 Shader Complexity、Quad Overdraw、Nanite Visualization。
- Unity：Profiler、Frame Debugger、Rendering Debugger（Overdraw）。
- 通用：RenderDoc。

半透明（玻璃、粒子、霧片）與大量貼花是最常見的 GPU 瓶頸；面數通常不是。

## 7. 製作順序

和概念設計的建議一致：先格局、再光、再材質、最後細節。

| 順序 | 做什麼 | 管線 |
|---|---|---|
| 1 | 參考：文字描述就是參考，每個空間先列出尺寸、材質、光源 | AGENT.md 步驟 0 |
| 2 | 灰盒：只有模組件，確認格局、比例、動線 | `layout.json` 只寫 `rooms` → `kit` → `engine` |
| 3 | 光：太陽、燈具陣列、霧、後處理 | `layout.json` 的 `lights` / `lighting` |
| 4 | 材質：表面材質換成正式的 | `materials` |
| 5 | 主要物件 → 中型細節 → 小雜物 | `props`、`scatter` |
| 6 | 貼花、植被、粒子 | `decals`（植被用引擎的 Foliage / PCG） |
| 7 | 色彩校正、效能檢查 | `post`、`budget.json`、引擎 profiler |
